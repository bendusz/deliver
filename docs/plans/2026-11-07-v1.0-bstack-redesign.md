# bstack 1.0 redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Strip the deliver plugin down to a T3-first PM skill: prose, templates and one log
script. Then rename it bstack.

**Architecture:**
- The PM skill (SKILL.md plus seven references) orchestrates children through T3
  `delegate_task`.
- Roles are "souls" in `references/roles.md`, pasted into each child's task.
- Every hook, Node script, test suite, agent file and `validate.sh` is removed. The only code is
  `scripts/log.sh`, which appends lines to a tracked `docs/log.md`.

**Tech Stack:** Markdown, JSON templates, one bash script, git, the T3 Code MCP tools.

**Spec:** `docs/specs/2026-11-07-v1.0-bstack-redesign.md` (abbreviated "spec §N" below). Every
implementer reads the spec sections their task names before starting.

**T3 dispatch**
- `delegate_task` target shapes:
  - Claude: `{"providerInstanceId":"claudeAgent","model":"<id>","options":{"effort":"<level>"}}`
  - Codex: `{"providerInstanceId":"codex","model":"<id>","options":{"reasoningEffort":"<level>"}}`
  - Codex `reasoningEffort` is always set.
- `clientRequestId`: `<story-id>-<role>-<round>`.
- Builders use `isolation: "worktree"`. Reviewers and verifiers use `isolation: "shared"`, pointed
  at the recorded worktree path.

**Story formats**
- Builder brief requirements (spec §15 results):
  - The child first runs `git switch -c pm/S<sprint>-<n>-<slug>` and commits there.
  - It ends with one fenced JSON block:
    `{"status":"done|blocked","branch":"…","worktree":"<git rev-parse --show-toplevel>","commit":"<sha>","tests":"<command and result>","notes":"…"}`.
- Story `pm-meta` line:
  `<!-- pm-meta: {"builder":"<auto|claude|codex>","touches":["<repo-relative path>"]} -->`
- Story `pm-exec` line, added at claim:
  `<!-- pm-exec: {"role_model":"<role provider/model effort>","thread":"<childThreadId>","branch":"pm/S<sprint>-<n>-<slug>","worktree":"<absolute path>","status":"<claimed|building|built|reviewing|fixing|verified|merged|blocked>","rounds":0,"verifier":"<PASS|FAIL|UNKNOWN> <sha>"} -->`.
  `verifier` is absent until the first verification.
- `docs/approval.json`, once approved:
  `{"status":"approved","approved_at":"<YYYY-MM-DD HH:MM>","plan_commit":"<sha>"}`. The template
  has `"status":"pending"` and the other two fields `null`.

**Log**
- The log is `<main checkout>/docs/log.md`, tracked.
- Each line is `YYYY-MM-DD HH:MM  <message>`, with two spaces after the time.
- The header is `# Decision log`. Messages are at most 100 characters.
- The PM invokes it as `bash "${CLAUDE_PLUGIN_ROOT}/scripts/log.sh" "<message>"`.

**Kept rules**
- Hard rules kept in SKILL.md (spec §8):
  - PM never writes implementation code.
  - No build before sign-off (conversation style).
  - Git is the record.
  - The reviewer is never the builder.
  - The PM runs the gates itself.
  - 3-round fix cap, then escalate.
  - No secrets in files.
  - Never push, force, or run destructive git without asking.
  - Never remove a dirty worktree.
- Caps: 3 fix rounds per story, at most 3 concurrent builders.

## Review Focus

1. **Plugin bleed.** A T3 Claude child loads this plugin and sees the `project-manager` skill
   (spec §15 result 4). The child must not start acting as a PM. Guarded in Task 3 (the opening
   line on every soul) and Task 7 (the SKILL.md child guard). Both tasks check with `grep`.
2. **Dangling references to removed machinery** in surviving prose. Examples: agent names like
   `expert-builder`, hooks, `validate.sh`, `tmp/log.md`, `/deliver:handoff`, tiers, panels,
   holdouts, `test-integrity`. A user following them hits missing files. Task 7 and Task 8 run
   the sweep grep.
3. **A Codex child dispatched without `reasoningEffort`** silently runs at T3's per-model
   default, which can be `low`. Task 3 and Task 4 grep for it.
4. **`log.sh` edge inputs**: multibyte characters (counted as characters, not bytes), a leading
   `-`, a `%` or a backslash, a call from a worktree or a subdirectory, and a call outside a
   repo. Pinned by Task 2's smoke cases.
5. **T3 absent.** The PM must stop with a clear "requires T3 Code" message, not half-run.
   Task 7 greps SKILL.md and doctor.md for it.
