# v0.16c — AGENTS.md instructions layer and release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `AGENTS.md` the canonical, minimal project instructions file the PM scaffolds, with `CLAUDE.md` as a one-line `@AGENTS.md` bridge; teach every agent and command to read it; add doctor checks; dogfood it in this repo and the example; ship 0.16.0.

**Architecture:** Two templates replace one. A short new reference, `instruction-layers.md`, records which layer holds facts, procedure, constraints, and persona so the template never regrows. All prose edits are exact string replacements listed per file. The release task bumps `plugin.json`, writes the CHANGELOG entry covering plans v0.16a, v0.16b, and this one, and runs the full validation.

**Tech Stack:** Markdown, JSON, bash validate script. No code beyond validate checks.

**Spec:** `docs/specs/2026-09-03-v0.16-agents-md-and-codex-runtime.md` (sections A, B, E, F, Migration, Acceptance criteria).

## Global Constraints

- `CLAUDE.md` bridge content is exactly two lines: `@AGENTS.md` then the HTML comment `<!-- Claude Code only. Everything shared with other agents belongs in AGENTS.md. -->`. Symlinks are never created.
- `templates/AGENTS.md.template` is at most 45 lines including blanks; filled files target 30 to 40 lines; hard limits 200 lines and 32 KiB are checked by doctor, not the template.
- Existing `CLAUDE.md` or `AGENTS.md` files are never overwritten; the PM shows a diff and asks.
- No agent prompt may mention `CLAUDE.md` on a line that does not also mention `AGENTS.md` (validate check).
- `SOUL.md` is not adopted; the mapping lives in `references/instruction-layers.md`.
- Version becomes `0.16.0` in `plugins/pm-skill/.claude-plugin/plugin.json` and at the top of `CHANGELOG.md`.
- Branch `feat/v0.16-node-runtime` (continues plans v0.16a and v0.16b). Commit after every task.

```markdown
# Instruction layers

Four layers carry what an agent needs. Keep each thing in exactly one of them.

| Layer | Holds | Where it lives | Loaded |
|---|---|---|---|
| Facts | commands, layout, non-default conventions, gotchas, safety norms | `AGENTS.md` (Claude Code reads it through the `@AGENTS.md` line in `CLAUDE.md`; Codex, Cursor, and Copilot read it natively) | every session, every subagent dispatch |
| Procedure | phases, checklists, hand-off contracts, review and verification rules | this skill's `SKILL.md` and `references/` | on demand, one reference per phase |
| Constraints | sign-off, secrets, actor isolation, `pm-meta.touches` | the bundled hooks and the Codex runner | enforced mechanically |
| Persona | role, tone, boundaries, stop conditions | each `agents/*.md` body; the runner prompt for Codex | per dispatch |

## Rules
- `AGENTS.md` is written once from `templates/AGENTS.md.template` and stays under 200 lines and
  32 KiB (the Codex budget). Every subagent receives the whole file on every dispatch, so each
  extra line is paid many times over. The test for a line: would removing it cause mistakes?
- Never copy procedure or hard rules from this skill into `AGENTS.md`. The hooks enforce them and
  the skill explains them; a restatement drifts and costs context.
- `CLAUDE.md` is a bridge: its first line is `@AGENTS.md`. Claude-only notes may follow it; keep
  them rare. Symlinks are not used (Windows needs Developer Mode; git needs `core.symlinks`).
- `SOUL.md` files (an OpenClaw convention for persona) are not created by the PM. Neither Claude
  Code nor Codex loads them; the agent bodies already carry the persona. A project author who
  keeps one may import it from the bridge file.
- Path-scoped constraints that only matter inside one directory go in `.claude/rules/<name>.md`
  with a `paths:` frontmatter (Claude Code) and a nested `<dir>/AGENTS.md` (Codex). The scaffold
  offers this for `pm/` at `standard` scale and above (`Instruction rules: pm-state`).

## Migrating an existing project
- `CLAUDE.md` exists, `AGENTS.md` does not: propose moving the content into a new `AGENTS.md`,
  trimmed to the template shape, and replacing `CLAUDE.md` with the bridge. Show the diff and
  ask. On refusal, leave both files alone and log that the project keeps a standalone `CLAUDE.md`.
- Both exist and `CLAUDE.md` is not a bridge: leave both, log a WARN; `/pm-skill:doctor` reports it.
```
