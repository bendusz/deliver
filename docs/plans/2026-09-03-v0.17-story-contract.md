# v0.17 story contract and agent budget Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `pm-meta` the only home for a story's builder and touch paths, bring every agent body under its word budget without losing a rule, trim the Codex build prompt and the session hook, and ship 0.17.0.

**Architecture:** One code task changes the parser and its fixtures and keeps legacy stories working. One prose task updates every consumer of the removed header fields. Two rewrite tasks bring the fourteen agent bodies under budget, seven each. One runtime task trims the prompt and the hook and adds the em dash check. One release task bumps the version.

**Tech Stack:** Node 20 ESM, `node:test`, Markdown, bash validate script.

**Spec:** `docs/specs/2026-09-03-v0.17-story-contract-and-agent-budget.md`

## Global Constraints

- Writing standard for every line of prose: `plugins/poteto/skills/unslop/SKILL.md`. No em dashes anywhere in files this plan touches.
- Agent frontmatter fields `name`, `tools`, `model`, `effort`, `color` never change (validate check 14 pins model and effort for all 14 agents).
- Literal tokens the PM parses survive verbatim: `block`, `major`, `minor`, `PASS`, `CONCERNS`, `FAIL`, `done`, `blocked`, `STATUS: PASS | FAIL | UNKNOWN`, `UNAVAILABLE`, and every runner envelope field name an agent lists.
- Runtime code is Node ESM only; no bash or jq under `plugins/pm-skill/hooks/` or `plugins/pm-skill/scripts/`.
- The actor-id salt `:pm-skill` in `hooks/lib.mjs` never changes.
- `bash scripts/validate.sh` must end `validate.sh: OK` and `node --test plugins/pm-skill/scripts/tests/` must be green at the end of every task.
- Branch `feat/v0.17-story-contracts`. Commit after every task. Never push.

```js
  const builderLine = head.map((l) => l.match(/^Builder:\s*(.*?)\s*$/)).find(Boolean);
  if (builderLine && builderLine[1] !== meta.builder) throw blocked('story pm-meta builder does not match the visible Builder field');

  // The capture starts after the FIRST `Touches:` on the line, so a second label stays in
  // the value and fails the path checks below. That is the safe reading of an odd line.
  const touchesLine = head.map((l) => l.match(/Touches:\s*(.*)$/)).find(Boolean);
  if (touchesLine) {
    const visibleRaw = touchesLine[1].trim();
    if (visibleRaw === '' || visibleRaw === '-' || /[<>]/.test(visibleRaw)) throw blocked('visible Touches must match bounded story pm-meta touches');
    const visible = [];
    for (let item of visibleRaw.split(',')) {
      item = item.trim().replace(/\/+$/, '');
      if (!item) throw blocked('visible Touches contains an empty path');
      const scope = pmRelpath(root, item);
      if (scope === null) throw blocked('visible Touches contains an invalid path');
      visible.push(scope);
    }
    if (JSON.stringify([...new Set(visible)].sort()) !== JSON.stringify(machine)) throw blocked('story pm-meta touches does not match the visible Touches field');
  }
  return { builder: meta.builder, scopes: machine };
```
