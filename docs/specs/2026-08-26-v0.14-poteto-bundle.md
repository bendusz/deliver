# v0.14 poteto companion plugin specification

Date: 2026-08-26

## Problem

pm-skill orchestrates delivery but says little about how a builder should think, how a review panel
should triage its findings, how docs should read, or how to prove an app works by driving it.
Lauren Tan's pstack (`https://github.com/cursor/plugins/tree/main/pstack`, MIT) covers exactly that
layer, but ships as a Cursor plugin with Cursor model slugs, Cursor subagent parameters, and Cursor
paths. A hand-patched copy already lives in one developer's `~/.claude/skills/`, which is neither
portable nor attributed.

## Goals

- Ship the pstack skills that complement pm-skill as a second plugin in this marketplace, `poteto`,
  installable with one command on any Claude Code machine.
- Keep every file attributable to its author. Her MIT license and copyright ship verbatim, and a
  short README credits her and links upstream.
- Patch only what Claude Code needs (models, subagent parameters, paths, tool names) and record every
  patch so the port can be re-synced against upstream.
- Teach pm-skill's references to use these skills when present, without making them a dependency.
- Validate the new plugin in the same CI run as pm-skill.

## Non-goals

- Porting `poteto-mode`, its playbooks, or `poteto-agent`. They are an orchestration entry point
  with the opposite autonomy rule to pm-skill's sign-off gate.
- Porting `swarm`, `figure-it-out`, `recall`, `show-me-your-work`, `tdd`, `no-comments` and Comment
  Sicko, `automate-me`, `setup-pstack`, or the Benny automations. Each duplicates something pm-skill,
  superpowers, or the Claude Code harness already provides, or is Cursor-only.
- Any hook, agent, or command in the `poteto` plugin. Skills only.
- Removing the developer's user-level copies in `~/.claude/skills/`. That is a manual step after
  install.
- Changing any pm-skill hard rule.

## Plugin layout

```
plugins/poteto/
├── .claude-plugin/plugin.json   # name poteto, version 0.14.3, license MIT, author Lauren Tan
├── LICENSE                      # upstream MIT text, unmodified
├── README.md                    # tribute, scope, what changed, how to re-sync
├── PORT.md                      # upstream SHA, per-skill patch table, exclusion list
└── skills/<name>/SKILL.md       # 35 skills
```

The plugin version mirrors the upstream pstack release it was ported from so a reader can tell at a
glance which pstack a given `poteto` tracks. `PORT.md` records the exact upstream commit.

`.claude-plugin/marketplace.json` gains a second entry with `source: ./plugins/poteto`.

## Skill inventory

Fourteen workflow skills: `how`, `why`, `unslop`, `architect`, `arena`, `blast-radius`,
`interrogate`, `technical-writing`, `create-verification-skill`, `maintain-verification-skill`,
`reflect`, `teach`, `typescript-best-practices`, `bro`. All 21 `principle-*` skills.

The set is the dependency closure of the skills pm-skill's references will name. `architect` runs
`arena`, `how`, and `why`. `blast-radius` runs `why` and `arena`. `architect` names `interrogate`.
`technical-writing` and `teach` name `unslop`. Everything names principles.

Skills already patched in the developer's `~/.claude/skills/` port (`how`, `why`, `architect`,
`arena`, `create-verification-skill`, and the unpatched `unslop`, `blast-radius`, `bro`,
`principle-*`) are copied from that port. Upstream did not change any of those files after the port
commit `60c641e`. The six new skills are copied from upstream `main` at the SHA recorded in `PORT.md`
and patched fresh.

## Patch rules

Every patch falls into one of these classes. `PORT.md` lists each occurrence.

1. Model slugs. `claude-fable-5-thinking-max` becomes `fable`, `claude-opus-5-thinking-xhigh`
   becomes `opus`, `grok-4.6-fast-xhigh` becomes `sonnet`, `gpt-5.6-sol-max` becomes "one Codex CLI
   run" named as an optional cross-family voice. Panel defaults become `fable`, `opus`, `sonnet`.
2. Subagent parameters. `subagent_type: generalPurpose` becomes `general-purpose`. `readonly: true`
   becomes `subagent_type: Explore`. `readonly: false` (needed for MCP access) becomes
   `general-purpose` with a note that `Explore` strips MCP tools.
3. Config lookups. Every `~/.cursor/rules/pstack-models.mdc` sentence is removed; the inline default
   stands.
4. Paths. `.cursor/skills/` becomes `.claude/skills/`. Cursor's `agent-transcripts/` becomes
   `~/.claude/projects/<slug>/<session>.jsonl` with subagent transcripts under
   `<session>/subagents/`. The slug is the workspace path with `/` replaced by `-`.
5. Tool names. Cursor's `create-skill` becomes "your skill-authoring skill, if one is installed".
   `AskQuestion` becomes `AskUserQuestion`. `Task` stays, since Claude Code's `Agent` tool is
   described as Task in most prompts and the model resolves it.
6. Namespacing. Slash references inside skill bodies (`/how`, `/architect`, `/unslop`) become
   `/poteto:how` and so on. Prose references ("the **how** skill") stay as written.

Nothing else changes. Wording, structure, and voice are hers.

## pm-skill integration

CONTRIBUTING.md forbids anything under `plugins/pm-skill/` depending on another plugin. The edits
below therefore describe a capability and cite the `poteto` skill as the example, in the same way
the Codex CLI is cited today. The PM already has licence to prefer a specialised skill when one
exists (SKILL.md, "Environment").

- `references/planning-and-signoff.md`, section 0. If a design-exploration skill is installed (for
  example `poteto:architect`), run it for the plan's Architecture section on greenfield work and for
  any decision with more than one viable shape.
- `references/decomposition.md`, story readiness. An Architecture-sensitive story may run
  `poteto:architect` before it is build-ready; its synthesized sketch goes into the story's Context.
- `references/review-gates.md`. Add the triage buckets Act on / Consider / Noted / Dismissed and the
  filtering rules (nitpick gravity, hypothetical versus actual, "I would have done it differently")
  to the existing triage step, credited to pstack's `interrogate`. Name `poteto:blast-radius` as an
  optional lens for a small diff into shared code.
- `references/implementation-loop.md`, step 7. PR and merge-commit bodies use the sections Why,
  Scope, Tradeoffs, Blast radius, Verification, dropping any that are empty.
- `references/verification.md`. When `.claude/skills/verify-<app>/` exists, `pm-verifier` drives
  the app through it and cites the evidence it captures.
- `commands/handoff.md`. Before writing the handoff, check that each `pm/log.md` entry from this
  session maps to a real commit, file, or command, and correct any that do not.
- `agents/technical-writer.md`. Apply a technical-writing standard skill when one is installed (for
  example `poteto:technical-writing`).
- `templates/constitution.md.template`. The Principles section offers the 21 principle names as a
  menu the project may adopt.

## Validation

`scripts/validate.sh` gains checks for the second plugin:

- `plugins/poteto/.claude-plugin/plugin.json` parses and its `source` in the marketplace resolves.
- `plugins/poteto/LICENSE`, `README.md`, `PORT.md` exist.
- Every `plugins/poteto/skills/*/SKILL.md` has `name:` and `description:` frontmatter and passes the
  strict YAML scalar check already applied to pm-skill agents.
- No Cursor-only string survives under `plugins/poteto/`: `.cursor/`, `grok-4`, `sol-max`,
  `thinking-max`, `generalPurpose`, `pstack-models`, `agent-transcripts`.
- The skill count under `plugins/poteto/skills/` equals the count listed in `PORT.md`.

CI runs `validate.sh` unchanged.

## Acceptance criteria

- `/plugin install poteto@pm-skill` on a clean Claude Code install registers 35 skills named
  `poteto:<name>`.
- `bash scripts/validate.sh` passes and `shellcheck` passes on every script it covers.
- `plugins/poteto/LICENSE` is byte-identical to upstream `pstack/LICENSE`.
- `PORT.md` lists every patched line by skill and class, the upstream SHA, and every excluded skill
  with its reason.
- `grep -r superpowers plugins/pm-skill/` still finds nothing. pm-skill references cite `poteto:*`
  skills only as optional examples.
- The existing `~/.claude/skills/*` port files match their `plugins/poteto/skills/*` counterparts
  except for the namespacing patch.
