# v0.18: project wiki and librarian agent

Status: approved by the user on 2026-09-04. Source: workstream WS4 of
`docs/specs/2026-09-03-v0.16-knowledge-restructure-proposal.md`, whose decisions 3 (`docs/wiki/`)
and 4 (on at `standard` scale) the user accepted. Writing standard:
`plugins/poteto/skills/unslop/SKILL.md`.

## Purpose

The PM writes about twenty artifact types and none is indexed or cross-linked. A returning agent has
no cheap way to ask "what do we know about X" without scanning `docs/`. This release adds a small
LLM-maintained wiki under `docs/wiki/` with one writer, the `librarian` agent, and wires it into the
resume path, the implementation loop, and `/pm-skill:analyze`. Raw artifacts, state, and the log do
not move.

## A. Layout

Three layers, mapped onto what exists:

- **Raw sources**, unchanged and immutable once written: `docs/spec.md`, `docs/plan.md`,
  `docs/constitution.md`, `docs/stories/*`, `docs/research/*`, `docs/verification/*`,
  `docs/completion-report.md`, and Codex review reports.
- **State and log**, unchanged: `pm/pm-state.json`, `pm/actors/*`, `pm/log.md`.
- **Wiki**, new: `docs/wiki/index.md` (one line per page), `docs/wiki/schema.md` (the conventions,
  written once from a template), `docs/wiki/decisions/<slug>.md`, `docs/wiki/concepts/<slug>.md`,
  `docs/wiki/sources/<slug>.md`.

Every page starts with a title line and one field line: `Type: <decision|concept|source> · Status:
<current|superseded by <slug>> · Sources: <repo-relative path[, path]>`. A decision page
adds `context` and `decision` sections. A concept page holds the durable explanation. A source page
summarises one raw artifact and cites it.

`index.md` is a flat list, one line per page: `- [<title>](<relative path>): <one sentence>`. At
about 150 entries the librarian splits it into one index per directory and keeps the root index as a
list of those three.

## B. The librarian agent

`agents/librarian.md`: model `sonnet`, effort `medium`, tools Read, Grep, Glob, Write, Edit. Body
budget 230 words. It is the only writer under `docs/wiki/` and writes nowhere else: never raw
sources, never `pm/`, never code. It never deletes a page; it marks `status: superseded by <slug>`.
It searches the index before creating a page, links every new page from at least one existing page
and the index, and cites a source path on every claim. It never runs git.

Modes, chosen by the first word of the dispatch:

- `ingest <path>[ <path>...]`: for each raw artifact, write or update its source page, then write or
  update the concept and decision pages it supports, then the index. Return a receipt under ten
  lines: pages created, pages updated, pages superseded.
- `query <question>`: read the index first, then the pages it points to, then answer with page and
  source citations. Return the answer and, when the answer is not yet on a page, the one-line
  proposal to file it.
- `lint`: report orphan pages, index entries that do not resolve, pages whose `sources` no longer
  exist, contradictory decisions with the same subject and both `current`, and concepts named in
  three or more pages that have no page. Fix index and link defects itself; report the rest.

## C. Hand-off points (the PM sorts nothing)

`references/knowledge.md` (new, under 350 words) owns the rules below; the phase references carry
one pointer sentence each.

- After spec sign-off: `ingest docs/spec.md`. After plan sign-off: `ingest docs/plan.md`, and the
  plan's decisions and risks become decision pages. After `docs/constitution.md` is written: ingest
  it.
- After every research report: ingest it.
- In the implementation loop, at state 7 (log, then next story): ingest the shipped story file and
  its verification report when one exists.
- After `/pm-skill:correct-course`: ingest the revised artifacts; the librarian supersedes.
- At every sprint boundary and before the completion report: `lint`. `technical-writer` receives
  `docs/wiki/index.md` as an input for the completion report.
- The PM logs one line per librarian dispatch in `pm/log.md` (the librarian never writes the log)
  and commits wiki changes together with the work they describe.
- Brownfield entry: on the first resume of a `standard` or larger project with no `docs/wiki/`, the
  PM offers one backfill `ingest` over the existing raw artifacts. Never automatic.

Scale: off at `tiny` and `small`; on at `standard` and above; at `regulated` a clean `lint` is
required before the completion report.

## D. Readers

- `commands/resume.md` and the "On resume" section of `references/logging-and-state.md`: after state
  and handoff, read `docs/wiki/index.md` when it exists, before scanning `docs/`.
- `codebase-analyst` and `researcher` dispatches on a project with a wiki include the index path as
  an input (a sentence in `references/knowledge.md`; the agent bodies do not change).

## E. Hooks and analysis

- `hooks/session-context.mjs`: when `docs/wiki/index.md` exists, print one line,
  `wiki: docs/wiki/index.md (<n> entries)`, where `<n>` counts lines starting with `- `. Fail-open.
- `hooks/pm-secrets-guard.mjs`: scope becomes `pm/` or `docs/wiki/`; message names the matched
  prefix. Ingested sources can carry secrets.
- `references/artifact-consistency.md` gains a `Wiki` detector group, run only when `docs/wiki/`
  exists: an index entry that does not resolve; an orphan page; a plan decision with no decision
  page; two `current` decision pages on one subject; a story that cites a `superseded` concept page.
  Severity `HIGH` for the contradiction, `MEDIUM` for the rest.

## Out of scope

- A second log, wiki search tooling, or any runtime code beyond the two hook edits.
- Automatic commits by the librarian.
- Changes to poteto skills (vendored, MIT).
- Wiki links to SpecDD `.sdd` files (WS5, next release).
