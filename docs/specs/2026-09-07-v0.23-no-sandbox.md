# v0.23: Codex runs unsandboxed

Status: approved by the user on 2026-09-07 ("Ok go with it", after choosing "OS sandbox in every
mode" for the reason "Codex needs more capability"). Writing standard:
`plugins/poteto/skills/unslop/SKILL.md`.

## Purpose

The Codex runner wrapped every run in two layers: an OS sandbox (`workspace-write` with network off
for build and fix on POSIX, `read-only` for review, advise, and research, and `danger-full-access`
on Windows because its sandbox refuses most shell commands) and a lockdown that ignored the user's
Codex config, pinned MCP servers and web search off, and disabled hooks and subagents. The user
wants Codex to have the capability it has in their own shell: network, MCP servers, web search, and
their own config. The sandbox is not what withheld those, the lockdown was, so both layers change.

## A. What changes

| Surface | Before | After |
|---|---|---|
| Sandbox, build and fix | `--sandbox workspace-write` plus network off and `/tmp` excluded on POSIX; `danger-full-access` on Windows | `-c sandbox_mode="danger-full-access"` on every platform, in the shared flag set |
| Sandbox, review codebase scope, advise, research | `--sandbox read-only` | the same shared `sandbox_mode` override; `--sandbox` is never passed, because `codex exec review` rejects it |
| `--ignore-user-config`, `--strict-config` | every mode | dropped, so `$CODEX_HOME/config.toml` loads and an unknown key in it cannot abort a run |
| `mcp_servers={}`, `web_search="disabled"` | every mode | dropped; research `--search off` still pins `web_search="disabled"`, and `--search auto` still adds `--search` when the CLI has it |
| Builder prompt | "Do not use the network, change git state, or edit ..." | "Do not change git state or edit ..." |
| Preflight required flags | `BUILD_FLAGS` and `READONLY_FLAGS` include `--sandbox`, `--ignore-user-config`, `--strict-config` | `BUILD_FLAGS` and `EXEC_FLAGS` without them; `REVIEW_FLAGS` likewise |
| Preflight `policy` envelope | two platform branches | one: `sandbox: danger-full-access`, `network_access: true`, `web_search: config`, `mcp_servers: config`, `host_tmp_writable: true` |

## B. What does not change

- `features.hooks=false` and `agents.enabled=false`. Codex hooks and subagents would run outside the
  runner's timeout and, for build and fix, outside the after-run audit.
- `--ignore-rules`, `--ephemeral`, the model and effort overrides, the output schema, the timeout,
  and the process-tree kill.
- `allow_login_shell=false`, the secret-filtered shell environment, and the worktree-local
  `tmp/codex-runtime/<run>` temp directory. The live smoke test still proves the filtering.
- The after-run audit in full: worktree snapshot, `pm-meta.touches` scope check, protected-path
  check, git metadata fingerprint. It is the only guard now, on every platform, which was already
  the Windows posture.
- The sign-off gate, the tracked-story requirement, and `--dangerously-bypass-approvals-and-sandbox`
  staying rejected by `parseArgs`.

## C. Trust boundary

A repository's `.codex/config.toml` and the user's `$CODEX_HOME/config.toml` become trusted inputs.
The tests that asserted a hostile project config is overridden are replaced by tests asserting the
config is left alone and only hooks and subagents are pinned off.

## Acceptance criteria

- AC-1: no runner argv carries `--sandbox`, `workspace-write`, `read-only`, `--ignore-user-config`,
  `--strict-config`, `mcp_servers={}`, or `sandbox_workspace_write.*`; every argv carries
  `sandbox_mode="danger-full-access"`, `features.hooks=false`, and `agents.enabled=false`.
- AC-2: `web_search="disabled"` appears only for research with `--search off`.
- AC-3: the preflight `policy` reports `danger-full-access` and `network_access: true` on every
  platform.
- AC-4: `docs/codex-cli-reference.md`, `README.md`, the `codex-review` command, and the
  `codex-builder` agent describe no read-only or workspace-write posture.
- AC-5: version and CHANGELOG at 0.23.0; `bash scripts/validate.sh` ends `validate.sh: OK`; the
  node tests are green.
