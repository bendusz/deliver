# v0.15 Opus focus specification

Date: 2026-08-27

## Problem

The seven gate-bearing Claude agents used the moving `opus` alias, and `expert-builder` used
`xhigh` effort by default. More reasoning does not by itself prevent lost context, scope expansion,
or premature completion. A focused worker needs current source evidence, an exact role boundary,
an observable stopping condition, and an orchestration check that does not trust its summary.

## Goals

- Pin all seven Opus roles to `claude-opus-5`.
- Use `high` for the broad builder, security auditor, and debugger; use `medium` for the other Opus
  roles. No shipped Opus agent may use `xhigh` or `max`.
- Give every Opus role a concise focus contract tailored to its job.
- Require agents to read current inputs and name missing evidence instead of filling gaps from
  memory.
- Derive changed paths from Git after every writer run and stop on any path outside the story's
  authoritative `pm-meta.touches`.
- Preserve the existing deterministic gates, independent review, verifier, and bounded retry loops.

## Non-goals

- Ship an Opus benchmark command, scorer, result schema, or telemetry store.
- Claim that prompt text is a security boundary.
- Override organization model policy or host-level Claude Code settings.
- Eliminate the existing builder comparison feature.

## Decisions

Each Opus agent prompt must tell the agent to re-ground itself in the supplied current artifacts,
stay within one named role and task, stop at that role's completion criteria, and return UNKNOWN or
blocked when decisive evidence is unavailable. Generic requests to double-check or perform extra
work are excluded.

For sequential work, the story branch remains uncommitted during build and fix, so the PM derives
the cumulative path set against `HEAD` plus untracked files after each writer. For parallel
worktrees, the PM derives each writer run's uncommitted path set against `HEAD` before committing
it. In both flows, paths must equal an allowed `pm-meta.touches` entry or be contained by an allowed
directory entry. An out-of-scope path stops the story before gates, review, or ship.

## Acceptance criteria

- All seven Opus agent files declare `model: claude-opus-5`.
- Their exact effort defaults are checked by `scripts/validate.sh`.
- No shipped Opus agent declares `xhigh` or `max`.
- Every Opus agent contains current-evidence, scope, stop, and missing-evidence guidance appropriate
  to its role.
- Sequential and parallel implementation instructions derive changed paths from repository state
  and reject paths outside `pm-meta.touches`.
- Doctor reports configured model and effort plus relevant host overrides.
- The Opus benchmark command, schema, scorer, and standalone configuration test are absent.
- README, changelog, model-tiering guidance, research, and plugin version agree.
