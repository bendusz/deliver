# v0.11 — model consolidation for the Claude 5 family design

Date: 2026-07-25
Status: approved
Origin: Opus 5 release — re-derive the shipped model/effort defaults for cost efficiency.

## Goal

Consolidate the agents' pinned model assignments now that Opus 5 has closed the capability gap
that justified Fable for code-writing. The judgement-heavy core of the workflow runs on one model
(`opus`), differentiated by reasoning effort instead of model tier; the two breadth/documentation
roles drop to `sonnet`. Net effect: cheaper than the v0.9.2 mapping (no Fable anywhere, two roles
one tier down) with quality concentrated where it counts.

### Rationale

- **Builder on `opus`/`xhigh`, not `fable`/`medium`.** With Opus 5, top-tier code-writing no
  longer requires the Fable/Mythos tier. The builder becomes the deepest-thinking agent in the
  fleet — effort (`xhigh`) is the lever, not model tier. It sits above the two `high`-effort
  analysts (`security-auditor`, `debugger`), which keep their targeted extra depth: they run
  rarely and only on hard problems, so the cost is small.
- **Light roles on `sonnet`.** `codebase-analyst` (breadth-over-depth survey) and
  `technical-writer` (documents already-shipped facts) are the two roles whose output quality is
  least sensitive to model tier. Everything gate-bearing (review verdicts, verification, tests)
  stays on `opus`.
- **Aliases, not full model IDs.** `opus` and `sonnet` resolve to Opus 5 / Sonnet 5 in current
  Claude Code and will auto-track future 5.x releases without a plugin release. Users who want a
  hard pin (including back to `fable`) override the agent's frontmatter, as today.
