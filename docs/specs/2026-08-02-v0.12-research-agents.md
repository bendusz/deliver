# v0.12 — research agents (`researcher` + `codex-researcher`) design

Date: 2026-08-02
Status: approved
Origin: the agent fleet has no external-research role — SKILL.md punts research to the built-in
`general-purpose`/`Explore` agents, which are not part of the plugin's dispatch model and write
nothing down.

## Goal

Add two agents that close the external-research gap:

- **`researcher`** — the default research agent: web-capable, sourced, writes durable reports.
- **`codex-researcher`** — an optional independent second-model opinion via the OpenAI Codex
  CLI, mirroring how `/pm-skill:codex-review` complements the review panel.

Both persist findings under `docs/research/` (research belongs in the repo, not session memory)
and return short digests so the PM's context stays clean (hard rule 2).

## Non-goals

- No new slash commands — `codex-researcher` is an agent, not a `/pm-skill:codex-research`
  command (decided 2026-08-01; the agent shape keeps raw research out of the PM's context).
- No change to the review panel, gates, or the existing codex commands.
- No "always run both" fan-out: two models on every question doubles cost for marginal gain.

## Agent 1: `researcher`

`plugins/pm-skill/agents/researcher.md`, structured like the existing nine.

| Field | Value |
| --- | --- |
| tools | `Read, Grep, Glob, WebSearch, WebFetch, Write` |
| model / effort | `sonnet` / `medium` (breadth role — same rationale as `codebase-analyst`) |

- **Job:** answer ONE tightly-scoped external question per dispatch — library/framework
  comparison, SDK/API facts, prior art, best practices, ecosystem scan — with sourced findings
  and an explicit recommendation.
- **When dispatched:** proactively in discovery, specification, and planning; reactively when a
  story is blocked on an unknown external dependency.
- **Write constraint (prompt-enforced):** may create/update `docs/research/*.md` only — never
  source, tests, or config. Read access to the repo is for grounding (what's already in use).
- **Report:** `docs/research/YYYY-MM-DD-<slug>.md` — question → context → findings (every claim
  cites a URL or file path) → options with trade-offs → recommendation → confidence + gaps.
- **Returns to PM:** a digest (≤ ~20 lines): recommendation, top 3 findings, report path.
- **Done means:** claims sourced; recommendation explicit; unknowns stated, not papered over;
  report written and path returned.

## Agent 2: `codex-researcher`

`plugins/pm-skill/agents/codex-researcher.md`. A Claude wrapper that drives the `codex` binary;
the research thinking happens inside Codex, the wrapper composes the brief and distills.

| Field | Value |
| --- | --- |
| tools | `Read, Grep, Glob, Bash, Write` |
| model / effort | `sonnet` / `medium` (orchestrates + distills; Codex does the thinking) |

- **Preflight:** `command -v codex` and `codex login status`. On failure return a structured
  **UNAVAILABLE** result (with install/login instructions) — not an error — so the PM degrades
  gracefully to `researcher` alone.
- **Run shape** (borrowed from `codex-help.md`, from the repo root):

  ```
  codex exec --sandbox read-only --ephemeral --color never \
    -m "$MODEL" -c model_reasoning_effort="$EFFORT" \
    -o <scratch file> "<self-contained research brief>"
  ```

  Defaults `gpt-5.6-terra` / `high` (codex-review's defaults), overridable via the dispatch
  prompt. Scratch file via `mktemp` **outside** the repo (no worktree contamination). Never
  `--dangerously-bypass-approvals-and-sandbox`, `--full-auto`, or `--yolo`. Codex knows nothing
  of the conversation — the brief must be self-contained (question, relevant paths, options
  weighed, constraints).
- **Report:** `docs/research/YYYY-MM-DD-<slug>-codex.md`, clearly attributed
  ("Codex (gpt-…) finds …"). The wrapper adds only a short note on where Codex's answer seems
  weak or unsupported; the **PM owns synthesis** across the two researchers.
- **Returns to PM:** digest with Codex's recommendation, the wrapper's caveats, report path —
  or UNAVAILABLE.
- **Build-time verification item:** whether the installed Codex CLI supports `--search`
  (native web search) with `codex exec`. If yes, the agent uses it for external questions; if
  not, Codex contributes model knowledge + repo reading only. Document the verified answer in
  `docs/codex-cli-reference.md` either way.

## Dispatch policy

`researcher` is the default research agent. `codex-researcher` is **risk-selected**: dispatched
alongside `researcher` for consequential or contested questions (framework choice, security
posture, anything the user flags) when the Codex CLI is installed — an independent second
opinion, never a replacement, exactly parallel to codex-review vs the review panel.

## Error handling

- `researcher` with no web access (tool denied/offline): report what came from the repo and
  model knowledge, mark web-dependent claims as unverified — never invent sources.
- `codex-researcher`: non-zero codex exit → report the stderr cause (auth, usage error) in the
  digest; keep the scratch/stderr evidence path. One failed researcher never blocks the other.

## Testing

  report lands in `docs/research/`, the digest is ≤ ~20 lines, and `codex-researcher` returns
  UNAVAILABLE cleanly when codex is absent (e.g. PATH-masked).
