# Knowledge restructure proposal (v0.16 to v0.18)

Status: PROPOSAL, not signed off. Date: 2026-09-03.

Five workstreams the user asked for, mapped against the plugin as it is today (v0.15.0), with a
proposed solution for each and the exact files each one touches. Research behind the
recommendations is summarised in the Evidence section at the end.

Workstreams:

1. AGENTS.md as the canonical instructions file, CLAUDE.md as a bridge
2. Minimise AGENTS.md scope (facts only; procedure in skills; persona in agent bodies)
3. All Codex invocations behind Sonnet wrapper agents
4. LLM Wiki under docs/wiki with a librarian agent
5. SpecDD skeleton phase (already discussed in chat; sequencing only here)

Proposed release order: 0.16 = WS1 + WS2 + WS3 (mechanical, low design risk, unblocks the rest).
0.17 = WS4 (wiki + librarian). 0.18 = WS5 (SpecDD skeleton). A plugin rename, if it happens,
fits best in 0.16 because the AGENTS.md template and every agent prompt are rewritten anyway.

---

## WS1. AGENTS.md canonical, CLAUDE.md bridge

### Facts that constrain the design

- Claude Code does not read AGENTS.md natively as of v2.1.259 (2026-09-02). The memory docs
  officially support two bridges: a CLAUDE.md whose first line is `@AGENTS.md`, or a symlink
  `ln -s AGENTS.md CLAUDE.md`. The docs recommend the import over the symlink.
- Codex reads AGENTS.md root-down (nearest file wins), with a 32 KiB total budget
  (`project_doc_max_bytes`). It does not read CLAUDE.md unless the project config lists it as a
  fallback filename.
- Cursor, Copilot cloud agent, Gemini CLI and about twenty others read AGENTS.md natively.
- Custom Claude Code subagents receive the whole CLAUDE.md hierarchy on every dispatch. Bloat is
  paid on every agent call, not once per session.

### Current state in the plugin

- `templates/CLAUDE.md.template` is the only instructions file the PM scaffolds
  (`references/planning-and-signoff.md` section 3). AGENTS.md is never written.
- Seven agents plus the Codex runner prompt say "read CLAUDE.md". The runner already says
  "read CLAUDE.md and repository AGENTS.md files when present".
- `hooks/require-signoff.sh` exempts `CLAUDE.md` from the pre-sign-off write block, not AGENTS.md.
- This repo itself has no CLAUDE.md, AGENTS.md, or `.claude/` directory.

### Proposal

- **Rename the template.** `templates/CLAUDE.md.template` becomes `templates/AGENTS.md.template`
  (content per WS2). Add `templates/CLAUDE.md.template` with a single line `@AGENTS.md` and a
  commented optional "Claude-only notes" section.
- **Scaffold step.** Write AGENTS.md. Then create the bridge: default to the `@AGENTS.md` import
  file. Offer the symlink as a documented alternative the user can choose at scaffold time
  (plan Delivery mode line: `Instructions bridge: import | symlink`). Reason for the default:
  Windows needs Developer Mode for symlinks, git needs `core.symlinks`, and an import file can
  carry Claude-only sections. If the user wants the symlink as default, it is a one-line change.
- **Existing-project rule** (keep the never-overwrite behaviour): if CLAUDE.md exists and
  AGENTS.md does not, propose moving the content to AGENTS.md and replacing CLAUDE.md with the
  bridge; show the diff and ask. Never do it silently.
- **Agent prompts.** Replace "read CLAUDE.md" with "read AGENTS.md; also read CLAUDE.md when it is
  not just a pointer" in: expert-builder, test-engineer, debugger, code-integrity-reviewer,
  security-auditor, architecture-reviewer, pm-verifier, technical-writer, and
  `scripts/codex-builder-run.sh` line 267.
- **Hooks.** Add `AGENTS.md` and `.claude/rules/*` to the pre-sign-off exemption list in
  `hooks/require-signoff.sh`; add a table-driven case to `scripts/test-hooks.sh`.
- **Doctor.** `/pm-skill:doctor` checks: AGENTS.md exists; CLAUDE.md resolves to it (symlink
  target or first-line import); AGENTS.md under 200 lines and under 32 KiB; report otherwise.
- **Dogfood.** Add a root `AGENTS.md` and a `CLAUDE.md` bridge to this repo (validate command,
  layout, version-coherence and model-pinning gotchas). Update `examples/todo-cli` the same way.
- **Validate.** Extend `scripts/validate.sh` check 8 so the renamed template is required, and add
  a grep that no agent prompt says "read CLAUDE.md" without also naming AGENTS.md.
- **Docs.** README install and scaffold sections, `references/planning-and-signoff.md`,
  `references/model-tiering.md` (override notes currently say "record in CLAUDE.md"), CHANGELOG.

Out of scope for 0.16: nested per-directory AGENTS.md files. WS5 (SpecDD) is the natural place
for per-module instructions later.

## WS2. Minimise AGENTS.md scope

### Facts

- Anthropic's current guidance: target under 200 lines; keep only facts needed every session
  (commands, layout, non-default conventions, "always do X" rules, gotchas); move procedures to
  skills and path-specific constraints to `.claude/rules/*.md` with `paths:` frontmatter; hooks are
  the enforcement layer. Test per line: "would removing this cause mistakes? If not, cut it."
- "Souls": SOUL.md is an OpenClaw convention (persona, tone, boundaries) loaded into the system
  prompt each session. Neither Claude Code nor Codex has native support. In Claude Code the
  equivalent persona layer is the subagent body in `agents/*.md`; in Codex it is the runner prompt.

### Current state

`templates/CLAUDE.md.template` is 33 lines, of which 11 are "Workflow rules (non-negotiable)"
that restate the skill's hard rules. Those rules are already enforced by the sign-off, secrets,
and actor-guard hooks and are repeated in every agent dispatch. The Architecture and layout
section will be superseded by the wiki (WS4) and the SpecDD root spec (WS5).

### Proposal

- **New `AGENTS.md.template`, target 30 to 40 lines:**
  - Project: one or two lines.
  - Commands: test, lint, build, run.
  - Pointers, one line each:
    - "This project is managed with the pm-skill plugin; process rules live in its skill and are
      enforced by hooks. Delivery state is in `pm/`; never edit another actor's `pm/actors/` file."
    - "Before answering questions about architecture, patterns, or decisions, read
      `docs/wiki/index.md`." (WS4; the one line every wiki adopter reports as mandatory.)
    - "Never push to a remote without an explicit request." (safety norm, not hook-enforced)
  - Conventions: only non-default ones.
  - Gotchas.
  - Dropped: the other workflow rules, file-by-file descriptions, anything derivable from code.
- **Persona ("souls").** Do not introduce SOUL.md files in managed projects. Map the concept
  onto what already exists: agent bodies in `agents/*.md` are the souls, `SKILL.md` and its
  references are the skills, AGENTS.md is the facts. Record this mapping in
  `references/model-tiering.md` or a short new `references/instruction-layers.md` so the PM never
  copies procedure into AGENTS.md again. If a project author wants a SOUL.md for their own
  agents, the bridge file can import it; the PM does not create one.
- **Path-scoped rules (optional, Claude-only).** The scaffold may write
  `.claude/rules/pm-state.md` with `paths: ["pm/**"]` carrying the state discipline from
  `references/logging-and-state.md`. It loads only when a file under `pm/` is read. Codex gets the
  same content via a two-line `pm/AGENTS.md`. Mark as opt-in at `standard` scale and above.
- **Doctor** warns on AGENTS.md over 200 lines, and lists lines that duplicate skill hard rules.
- **Files:** `templates/AGENTS.md.template`, `templates/CLAUDE.md.template`, new rule template,
  `references/planning-and-signoff.md`, `references/scale-profiles.md`, `commands/doctor.md`,
  README, CHANGELOG.

## WS3. Every Codex invocation behind a Sonnet wrapper

### Current state

| Surface | Who runs `codex` | Runner script | Sandbox |
|---|---|---|---|
| `codex-builder` agent | Sonnet wrapper (Bash only) | `scripts/codex-builder-run.sh` (strict config, preflight, exit codes, schema output) | workspace-write |
| `codex-researcher` agent | Sonnet agent, ad hoc `codex exec` in its own prompt | none | read-only |
| `/pm-skill:codex-review` | **the PM in the main session**, N parallel background processes, polling every 30 s | none | review / read-only |
| `/pm-skill:codex-help` | **the PM in the main session** | none | read-only |
| `/pm-skill:benchmark-builders` | dispatches `codex-builder` | via builder runner | workspace-write |

The two commands cost the orchestrator its context on polling and CLI mechanics, and the three
read-only surfaces each carry their own copy of the flag rules from `docs/codex-cli-reference.md`.

### Proposal

- **One read-only runner script.** Add `scripts/codex-exec-run.sh` with `--mode review|advise|
  research`, the same preflight, `--ignore-user-config --strict-config`, `--sandbox read-only`
  (omitted for `exec review`, which rejects it), `--ephemeral`, `-o` output file, stderr sidecar,
  timeout, and the existing exit-code vocabulary (65 rejected, 69 unavailable, 70 failed,
  124 timed out). Keep the write-capable builder runner separate; its safety surface is larger.
- **Two new Sonnet wrapper agents, Bash only, model `sonnet` effort `medium`:**
  - `codex-reviewer`: one objective per dispatch; returns a 15-line digest plus the report path.
    `/codex-review` becomes: PM composes objectives, dispatches N `codex-reviewer` agents in
    parallel with the Agent tool, relays digests. No polling in the main session.
  - `codex-advisor`: wraps `/codex-help`; returns the answer and a scratch path.
- **Refactor `codex-researcher`** to call the shared runner in `research` mode instead of its
  inline `codex exec` block. Its tools shrink to Bash plus Write (for the report).
- **Codify the rule** in `references/model-tiering.md`: the PM never runs `codex` from the main
  session; every invocation goes through a Sonnet wrapper and a bundled runner. Add the two agents
  to the pinned table and to `scripts/validate.sh` check 14.
- **Tests.** Extend the stubbed-codex pattern in `scripts/test-codex-builder.sh` into
  `scripts/test-codex-exec.sh` covering the three modes and the `exec review` flag exclusions.
- **Docs.** `docs/codex-cli-reference.md` gains the read-only runner section; `commands/
  codex-review.md` and `commands/codex-help.md` lose their inline CLI recipes; README agent table.

Alternative considered: one `codex-liaison` agent with a `Mode:` input. Rejected because the
plugin routes dispatch by agent description and the validate script pins per-agent regimes; three
thin agents sharing one script is less coupling than one agent with three behaviours.

## WS4. LLM Wiki under docs/wiki with a librarian agent

### Facts

- Karpathy's LLM Wiki has three layers: immutable raw sources, an LLM-owned wiki of markdown
  pages, and a schema document that tells the agent the conventions. Mandatory pages are an
  `index.md` (one line per page) and an append-only `log.md`. Operations: ingest, query, lint.
- Working implementations that scale past a few hundred pages all do the same four things:
  search before create, update index and log in the same operation, supersede instead of delete,
  and cite the raw source on every claim. Several use a dedicated curator agent as the sole writer
  (deepfounder's `wiki-curator`, Sonnet, reports in under 10 lines).
- Wikis suit durable knowledge, not session state or high-frequency logs. Machine state stays in
  JSON; the episodic record stays in an append-only log.
- Adopters report the wiki is ignored unless the instructions file says "read the index first".

### Current state

The PM writes about twenty artifact types (spec, plan, constitution, stories, research reports,
verification reports, checklists, completion report, Codex reviews, handoffs, state, log). None
is indexed or cross-linked. Decisions live in the plan's Risks section and in log lines. Resume
re-reads state, log, and handoff; a returning agent has no cheap way to ask "what do we know
about X" without scanning `docs/`.

### Proposal

- **Three layers, mapped onto what exists.**
  - Raw sources (immutable once signed off or written): `docs/spec.md`, `docs/plan.md`,
    `docs/constitution.md`, `docs/stories/*`, `docs/research/*`, `docs/verification/*`,
    `docs/completion-report.md`, Codex review reports. Unchanged locations.
  - State (not wiki): `pm/pm-state.json`, `pm/actors/*.json`, handoffs. Unchanged.
  - Log: `pm/log.md` is already the append-only episodic record. The wiki reuses it; librarian
    entries are prefixed `librarian`. No second log.
  - Wiki: new `docs/wiki/` with `index.md`, `schema.md`, `decisions/<slug>.md` (ADR-lite: context,
    decision, status, supersedes, sources), `concepts/<slug>.md` (domain and architecture
    concepts, one per page; later these link to `.sdd` files from WS5), `sources/<slug>.md` (one
    summary page per raw artifact with citations back to it).
- **`librarian` agent.** Model `sonnet`, effort `medium`; tools Read, Grep, Glob, Write, Edit.
  Writes only under `docs/wiki/` and appends to `pm/log.md`. Never edits raw sources, `pm/`
  state, or code; never deletes a page (marks superseded); searches before creating; every page
  links to at least two others and appears in the index; every claim cites a source path. Modes:
  - `ingest <path>`: summarise one raw artifact into a source page, update or create concept and
    decision pages, update the index, log one line. Returns a receipt under 10 lines.
  - `query <question>`: read the index first, drill into pages, answer with citations, offer to
    file the answer back.
  - `lint`: orphans, stale index entries, contradictions with dates, concepts mentioned in three
    or more pages that lack a page. Returns findings; fixes only index and link defects itself.
- **Orchestrator hand-offs (the PM sorts nothing).** Dispatch `librarian ingest` after spec
  sign-off, after plan sign-off (plan decisions become decision pages), after every research
  report, after every story ships (verification report plus story outcome), and after
  `correct-course` (supersession). Dispatch `librarian lint` at sprint boundaries and before the
  completion report. `technical-writer` reads the wiki for the completion report.
- **Resume path.** `/pm-skill:resume` reads `docs/wiki/index.md` after state and handoff, before
  scanning `docs/`. `codebase-analyst` reads the wiki first on a brownfield re-entry. poteto's
  `why` skill lists the wiki as its first evidence source when installed.
- **Hooks.** `session-context.sh` prints one line when `docs/wiki/index.md` exists (page count,
  last lint date from the log). `pm-secrets-guard.sh` extends its scope from `pm/` to
  `docs/wiki/` because ingested sources can carry secrets.
- **Analyze.** `/pm-skill:analyze` gains a wiki section: every plan decision has a decision page,
  every index entry resolves, no orphan pages, no story references a concept page that is stale.
- **Scale.** Off at `tiny` and `small`; on at `standard` and above; `regulated` requires a clean
  lint before ship.
- **Schema guardrails** written into `docs/wiki/schema.md` from a template: search before create,
  cite on every claim, supersede not delete, shard the index at about 150 entries, no automatic
  commits (the PM commits wiki changes with the work they describe).
- **Files:** new `agents/librarian.md`; new templates `wiki-schema.md.template`,
  `wiki-index.md.template`, `wiki-decision.md.template`; new `references/knowledge.md` (ownership,
  hand-off points, lint cadence); edits to `references/logging-and-state.md`,
  `references/implementation-loop.md`, `references/artifact-consistency.md`,
  `references/scale-profiles.md`, `commands/resume.md`, `commands/analyze.md`,
  `hooks/session-context.sh`, `hooks/pm-secrets-guard.sh`, `scripts/test-hooks.sh`,
  `scripts/validate.sh` (pin librarian at sonnet/medium), `SKILL.md` agents table, README, CHANGELOG.

Open question for the user: `docs/wiki/` (inside the tracked docs tree, covered by the sign-off
hook's docs exemption) versus a top-level `wiki/`. Recommendation: `docs/wiki/`.

## WS5. SpecDD skeleton phase

Design as discussed in chat: optional phase after sign-off and before decomposition, per sprint;
a `spec-architect` agent writes only `.sdd` files; stories point to `.sdd` files for Touches and
Context; reviewers and verifier receive the relevant `.sdd`; builders may edit the `.sdd` they own
but must report deviations. Sequenced after WS1 and WS4 because AGENTS.md carries the pointer to
`.specdd/bootstrap.md`, and wiki concept pages link to `.sdd` files. Not re-specified here.

## Cross-cutting

- **Validate script** changes per workstream are listed above; each release keeps
  `bash scripts/validate.sh` green and bumps the CHANGELOG heading with the plugin version.
- **Actor id salt** in `hooks/lib.sh` stays untouched by all five workstreams and by any rename.
- **Skill hard rules** are unchanged. The PM still writes no code; the librarian writes no code.
- **Rename**: if the plugin is renamed, do it in 0.16 with WS1, since every agent prompt and the
  scaffold templates are rewritten there anyway.

## Decisions needed from the user

1. Bridge default: `@AGENTS.md` import (recommended) or symlink.
2. Codex wrappers: three thin agents sharing one runner (recommended) or one agent with modes.
3. Wiki location: `docs/wiki/` (recommended) or `wiki/`.
4. Wiki default: on at `standard` scale (recommended) or opt-in everywhere.
5. SOUL.md: not introduced (recommended); agent bodies remain the persona layer.
6. Release order: 0.16 = WS1+WS2+WS3, 0.17 = WS4, 0.18 = WS5 (recommended).
