# v0.28: the October refresh

Status: scope narrowed by the user on 2026-10-11. The proxy-first Codex route, the proxy-home setup
script, the proxy and T3 doctor checks, and the T3 note are withdrawn as untested and too early. What
remains is the skill-stack work agreed after the research reports on pstack upstream, Opus 5.5
prompting, and Matt Pocock's skills. Writing standard: `plugins/poteto/skills/unslop/SKILL.md`.

## Problem

1. **Retries repeat the same attempt.** A builder that failed at its frontmatter effort is retried
   at the same effort, and a builder that reports done with criteria still open gets no targeted
   continuation.
2. **The debugger may theorise without a reproducer.** Nothing requires a fast failing command
   before a root cause is named.
3. **Reviews mix two questions.** `code-integrity-reviewer` reports "does it meet the story" and
   "is it sound code" in one list, so triage has to separate them.
4. **Stories can be horizontal layers.** `decomposition.md` does not ask for thin end-to-end slices
   and has no pattern for a wide refactor.
5. **Retro learnings all become prose.** A mechanical mistake is recorded as an `AGENTS.md` line
   when a check could prevent it.
6. **A typo in agent frontmatter passes validation.** `efort:` is silently ignored by Claude Code.
7. **The poteto bundle is behind upstream** (0.14.3 against 0.15.17).

## Design

### A. Loop changes

- **Escalating effort.** `fix-loop.md` and `implementation-loop.md`: `expert-builder` is dispatched
  at its frontmatter effort first. From fix round 2 on, and on a builder retry, the dispatch passes
  `effort: high`.
  - Source: Anthropic's effort guidance (try low first, escalate failures).
  - Requires Claude Code 2.1.292; on older versions the dispatch passes no `effort`.
- **Re-dispatching on open criteria.** When a builder reports done but acceptance criteria are still
  open, the PM:
  - waits for any background agents still running;
  - then sends one continuation that names the open criteria;
  - stops after 2 continuations and treats the story as blocked.
- **Prompt audit.** `/doctor prompt-audit` (2.1.283) ran over both plugins on 2026-10-11. Applied:
  references that told the PM to invoke user-invoked poteto skills now ask the user; a stale skill
  name, a dead pointer, two history leftovers, a pinned model name in an example and one
  capitalised modal are gone; `codex-reviewer` lost a line cap that could drop findings. Declined:
  the other sub-agent line caps (they protect the PM's context and drop nothing) and renaming
  "Task tool" across poteto (twelve deviations from upstream for no behaviour change).
- **Doctor.** Raise the minimum Claude Code version to `v2.1.292`.

### B. Matt Pocock adaptations

Source: `mattpocock/skills` (MIT). Adapt the ideas in deliver's own words, one credit line per file;
copy no files.

- **`debugger`: reproduce first.** The dispatch carries a fast command that reproduces the failure
  and its output. Without one, the debugger's whole return is the command to run, and the PM runs
  it and re-dispatches. The debugger stays read-only (`hardening.md`); the PM runs commands, as it
  does for the gates.
- **`code-integrity-reviewer`: two lists.** Spec findings (a criterion or `Specs` line unmet) and
  standards findings (correctness, security, conventions) are reported separately, followed by a
  short list of code smells graded `minor`.
- **`decomposition.md`: thin slices.** Each story cuts end to end through every layer it needs and
  is demonstrable alone. A wide refactor is three stories: expand, migrate, contract.
- **`retrospective.md`: check before rule.** A recurring mechanical mistake becomes a proposed
  lint rule, test, or gate. Only judgement calls become `AGENTS.md` lines.
- **`test-engineer`: TDD anti-patterns.** Tests that assert on mocks, mirror the implementation, or
  reach into internals are named as things not to write.

### C. Validation

`scripts/validate.sh` gets an allowlist of agent frontmatter keys: `name`, `description`, `model`,
`effort`, `tools`, `disallowedTools`, `color`, `maxTurns`, `autoCompactWindow`, `skills`,
`mcpServers`, `permissionMode`, `memory`, `isolation`. An unknown key fails validation. The 16
agents use only `name`, `description`, `model`, `effort`, `tools` and `color` today.

### E. Further improvements (chosen by the user on 2026-10-11)

- **Regression test per bug fix.** A fix round for a failing gate or a correctness finding lands
  with a test that fails before the fix and passes after. The fix brief names it; the builder
  reports the before and after result. A finding with no testable behaviour (naming, dead code)
  is exempt, and the brief says so.
- **Plan the app-driving check.** When the product has a UI or a running service, the plan carries
  a sprint-1 story that creates the `verify-<app>` skill, so criteria that need the running app do
  not come back `UNKNOWN`. `planning-and-signoff.md` owns the rule; `verification.md` points to
  it. `tiny` scale is exempt.
- **Retro numbers from git.** `scripts/retro-stats.mjs` reads the sprint's story files and prints
  fix rounds and retries per story and per builder, as JSON or a table. `/deliver:retro` runs it
  and the retro record carries the table. Node ESM, read-only, no dependencies.
- **Performance lens.** A new read-only `performance-reviewer` agent (Opus 5.5, `medium`), chosen
  only for stories on a hot path or handling large data. `review-gates.md`, `decomposition.md`
  and `artifact-consistency.md` name it wherever they name the other lenses. The fleet becomes 17
  agents.

### F. The orchestrator role (added by the user on 2026-10-11)

The user supplied a draft role for the main agent. Its concept is adopted in deliver's wording.

- **Role and responsibilities.** `SKILL.md` opens with the PM as an autonomous technical project
  manager who owns planning, delegation, quality, security and production readiness, followed by
  a short responsibilities list.
- **Autonomy.** After sign-off the PM decides and records the decision. It asks only at a cap, on
  a decision that is the user's, or before something hard to undo. Hard rule 3 (no implementation
  before sign-off) is unchanged.
- **Reporting.** The PM messages the user when asked, on escalation, and at the checkpoint in the
  plan's Delivery mode. Worded as when to report, since a blanket "no updates" rule makes current
  models under-report.
- **`docs/log.md`.** A timestamped ISO 8601 entry of 3 or 4 sentences at every significant story
  update. This partly reverses 0.24, which removed `pm/log.md`. The difference: nothing derives
  state from the new file, and `state.md` says git and the Execution block win a disagreement.
  `merge=union` keeps appends from conflicting.
- **Second model.** `codex-advisor` before a consequential technical decision, and
  `codex-reviewer` once per story beside the panel at `small` scale and above. The user set the
  runner defaults: advice on `gpt-6-astra` at `high`, review on `gpt-6.1-sol` at `high`.

### G. Self-improvement (agreed by the user on 2026-10-11)

Two research reports (self-improvement skills, recursive loops) agreed on the limits. Agent-written
skills score below no skills (SkillsBench, arXiv 2602.12670). Context files raise cost by over 20%
with no general gain (arXiv 2602.11988). Reward hacking rises with the number of optimisation
steps. Whole-file rewrites collapse a prompt (ACE, arXiv 2510.04618). No study covers delivery
work. So the design measures first, keeps a person on every merge, and prefers removal.

- **Version stamp.** The Execution block gains `deliver`, the plugin version at the claim.
  `retro-stats.mjs` groups counters by it. It prompts a look and proves nothing, since stories
  differ.
- **Lessons that expire.** At most three learned `AGENTS.md` lines per retro. Each ends with
  `[L<sprint>-<n>]`, and the record's Lessons table holds its evidence and review-by sprint.
  `retro-stats.mjs --audit` marks a line `due` when that sprint has arrived and no later retro
  cited it, and `orphan` when no retro recorded it. A proposed check must fail on the offending
  commit first. Only gates, reviewers, the verifier, and the user count as evidence, which keeps
  fetched text out of the rules.
- **Frozen evals.** `benchmarks/agent-evals`: 16 fixtures for `code-integrity-reviewer` and
  `pm-verifier`, in `dev` and `heldout` splits, pinned by a manifest that `validate.sh` checks.
  `scripts/agent-evals.mjs` scores a results file and compares two. `/deliver:agent-evals` runs
  the trials, three per case.
- **`/deliver:improve`.** One hypothesis and one edit of at most 20 lines per run, on an agent
  body or a reference. Accepted only when held-out, seeded, and clean passes do not fall, no
  reliably passing case breaks, and the prompt grows by no more than 10%. It never commits.
- **Known limits.** Three trials over a few cases detect a large loss and never a small gain.
  The trials run the prompt through a general-purpose subagent, so the agent's tool limits are
  not reproduced. Only two agents have fixtures. The fixtures have not yet been run against a
  model, so the baseline pass rates are unknown.

## Non-goals

- Any Codex route, proxy, Tailscale or T3 Code change.
- Installing Matt Pocock's plugin.
- Any change to the actor-id salt.
- Giving `debugger` a shell.
- Automatic writes to `AGENTS.md`, agent-written skills, and any unattended or nightly loop.
- Making the sign-off hook fail closed. The earlier design set `onFailure: "block"` on it, but the
  hooks reference at `code.claude.com/docs/en/hooks` (checked 2026-10-11) lists no such field, and
  an unknown key risks the whole hook file failing to load. Deferred until a source confirms it.
