# v0.19: hygiene release

Status: approved by the user on 2026-09-04 (hygiene scope, then section H with fallback option 1). Source: items parked by rulings R54 and R60 during the 0.17 and
0.18 Codex reviews (`codex/2026-09-03-2258-*` and `codex/2026-09-04-0053-*`), chosen by the user
over starting the SpecDD workstream. Writing standard: `plugins/poteto/skills/unslop/SKILL.md`.

## Purpose

Two review rounds found the same shape of waste: the PM loads whole references to use one branch,
templates and references both define the same fields, and the Codex contract is written out in
four places. This release removes that duplication so every later agent loads less. Behaviour is
unchanged except where a section names a code change.

## A. Clean-path implementation loop

- `references/implementation-loop.md` keeps the clean sequential path only: states 0 to 3, 5, 6,
  and 7, under 900 words (the merge message grammar it absorbs is about 90 of them).
- The fix state (today's state 4: triage, fix routing, the debugger, the three-round cap) moves to
  a new `references/fix-loop.md`, loaded only when a gate fails or a `block` or `major` finding is
  open. Every rule survives once; the loop keeps one pointer sentence at state 2 and state 3.
- The readiness check at state 0 is one sentence pointing at `decomposition.md`'s readiness section
  and the checklist template, not a restatement.
- `references/review-gates.md` splits: lens selection (about 150 words) stays in `review-gates.md`
  and the loop's state 3 names it; finding triage moves into `fix-loop.md`, where it is used.
- The merge and PR message grammar moves from `documentation.md` to the loop's state 6 (about 60
  words), because every ship needs it; `documentation.md` keeps the boundary work only.
- `verification.md` is loaded from state 5 only when the story proves itself by driving the app or
  needs a durable report; the loop says so in one clause.

## B. Templates own fields

- `references/planning-and-signoff.md` stops enumerating the plan's sections; it names
  `plan.md.template` and keeps only the semantic rules (what traceability must prove, what
  Delivery mode controls, the sign-off line). `templates/plan.md.template` gains a one-line comment
  per section that needs one so the template is self-explaining.
- `references/decomposition.md` stops restating the story header and sections; it names
  `story.md.template` and keeps the rules (what `pm-meta` must satisfy, when a story is
  build-ready, how lenses are chosen).
- `commands/handoff.md` becomes: fill `HANDOFF.md.template` from verified repository state, omit
  empty sections, audit this session's log entries, then synchronise timestamps, log, and commit.
  The content rules that repeat the template's own comments go; the audit rule and the no-secrets
  rule stay in the command because the template cannot enforce them.

## C. Codex contract in one place

- `docs/codex-cli-reference.md` documents the public runner flags, exit statuses, safety
  invariants, envelope fields a wrapper returns, and platform limitations. Internal argv order,
  per-mode `lockedExecArgs` detail, and snapshot mechanics are owned by `scripts/codex/**` and its
  tests; the reference points at them.
- `commands/codex-review.md` stops repeating the preflight flag validation and output-directory
  rejection the runner performs; it keeps parse, secret scan, dispatch, index, and log.
- `agents/codex-reviewer.md` stays as is (already within budget after 0.17).

## D. Builder result schema

- `schemas/codex-builder-result.schema.json` drops `out_of_scope_changes` and `risks`; a blocked run
  carries its reason in `root_cause`. `summary` gains `maxItems: 5`. `validateBuilderResult` in
  `scripts/codex/modes/build.mjs`, the stub in `scripts/tests/stub-codex.mjs`, the tests, the build
  prompt's JSON sentence, `agents/codex-builder.md`, and `docs/codex-cli-reference.md` follow.
- Success-envelope fields are unchanged (ruling R41 stands).

## E. Small code and test cleanups

- `scripts/codex/lib/spawn.mjs`: the local descendant-reaping routine is replaced by the existing
  `killTree()`; behaviour, signals, and fallbacks unchanged; existing process-cleanup tests pass.
- `scripts/tests/hooks.test.mjs`: the secret-scanner cases shrink to one clean case, one token
  match, one assignment match, the target-selection cases, and the stderr and exit-status
  assertions; `scripts/tests/lib.test.mjs` keeps the exhaustive patterns.
- `templates/verification-report.md.template`: the `## pm-verifier` section keeps `STATUS`, the
  per-criterion evidence rows, and `Action`; the duplicated gate-status and prior-review rows go,
  since the template's Gates and Review sections already hold them.

## F. Command trims and one frontmatter fix

- `commands/benchmark-builders.md`, `codex-help.md`, `codex-review.md`, `correct-course.md`,
  `doctor.md`, `handoff.md`, `resume.md`: remove rationale and branch-specific instructions that
  restate the action or a reference, per the round 5 token report's table. Every step an agent
  performs stays.
- `agents/technical-writer.md` description: inputs come "from the paths the PM names" rather than
  "the plan, pm/log.md, and story files". Frontmatter otherwise unchanged; validate check 4 must
  still parse it.

## H. Codex model defaults with fallback

- `gpt-6-astra` (released 2026-09-03) becomes the default model for every Codex mode in
  `scripts/codex/lib/args.mjs`: build, fix, review, research, and advise. Efforts are unchanged
  (high for build, fix, review, and research; medium for advise). `--model` still overrides.
- Fallback: on this machine the API answers `400 invalid_request_error` with "model is not
  supported when using Codex with a ChatGPT account". When a run's model was not set by `--model`
  and Codex exits non-zero with that error shape on its output, the runner retries the same command
  once on `gpt-5.6-sol` at effort `medium`, the same fallback for every mode, and records
  `model_fallback: {"from": {"model": "gpt-6-astra", "effort": "<effort>"}, "to": {"model":
  "gpt-5.6-sol", "effort": "medium"}, "reason": "<first line of the error>"}` in the envelope,
  with `model` and `effort` set to the values that produced the result. An explicit `--model` never
  falls back. Any other failure behaves as today.
- `scripts/tests/stub-codex.mjs` gains `STUB_UNSUPPORTED_MODEL=<name>`: when the requested `-m`
  equals it, the stub prints the API's error line and exits 1. Tests cover: fallback taken and
  recorded; explicit `--model` not falling back; a different error not falling back; success on
  the first try carries no `model_fallback` field.
- Every prose default follows the code: `agents/codex-advisor.md`, `agents/codex-researcher.md`,
  `commands/codex-help.md`, `commands/codex-review.md`, `docs/model-tiering.md`,
  `docs/codex-cli-reference.md` (which documents the fallback and the envelope field), `README.md`.
  Historical specs and plans under `docs/` keep their wording.
- The 0.19 Codex review round runs with the new default so the fallback is exercised live.
