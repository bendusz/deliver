# v0.24: git is the state

Status: approved by the user on 2026-09-07 ("Do it, then do max 2 rounds of Astra high reviews"),
after a design discussion and one Codex (`gpt-6-astra`, high) review of the proposal. Writing
standard: `plugins/poteto/skills/unslop/SKILL.md`.

## Purpose

For repository work, the tracked `pm/` state (a shared JSON, per-actor JSONs, a union-merged
logbook, and per-actor handoffs) duplicates what git and the tracked `docs/` artifacts already
carry. Branches are claims, commits are the record, the merge commit body is the story summary,
and the story file already holds the criteria and the verification evidence. Three things were
genuinely not in git: the approval signal the hooks and the Codex runner read, the in-flight loop
counters and builder route, and the actor's next step. This release keeps exactly those, in the
smallest tracked form, and removes the rest. Operational changes outside the repository (deploys,
migrations, secret rotation) are a later release.

## A. What replaces what

| Before | After |
|---|---|
| `pm/pm-state.json` (`signed_off`, approver, date, scale, phase, sprint counters, `assignments`) | `docs/approval.json`: `status` (`pending`, `approved`, `revoked`), `approver`, `approved_date`, `plan_digest` (the `git hash-object` blob id of `docs/plan.md` at approval), `updated`. Scale and integration branch live in the plan's Delivery mode. Phase and sprint are derived from which artifacts exist and which stories are merged. |
| `pm/actors/<id>.json` (position, builder, counters, batch, next) | An `## Execution` section at the end of each claimed story, holding one `<!-- pm-exec: {...} -->` JSON comment with `owner`, `builder`, `branch`, `status` (`claimed`, `building`, `built`, `in-review`, `merged`, `blocked`), `rounds`, `retries`, `updated`, plus optional dated note lines for skips, escalations, and blockers. Written at claim, updated and committed before every dispatch and after every round. |
| `assignments` claim map | The story branch `pm/S<sprint>-<n>-<slug>` plus the story's `owner`. Claiming is one commit on the integration branch that adds the Execution section, then the branch. A branch or an Execution block with another owner is a claim; a quiet one is possibly stale, never free to take. |
| `pm/log.md` | The commit history. The `--no-ff` merge commit body (Why, Scope, Tradeoffs, Blast radius, Verification) is the story record; `git log --first-parent <integration>` is the project log. Mid-flight events with no commit go into the story's Execution notes. |
| `pm/actors/<id>.HANDOFF.md`, staleness by JSON timestamps | `docs/handoff/<actor-id>.md`, with a `BASE_COMMIT` line. Stale when `HEAD` is no longer that commit. |
| `parallel_batch` | `git worktree list` plus each story's Execution block. |
| `.gitattributes` `pm/log.md merge=union`, `.claude/rules/pm-state.md`, `pm/AGENTS.md`, `Instruction rules: pm-state` | Gone. |

## B. Commit discipline

- Sequential path: after the builder returns and the scope check passes, commit the story's
  paths to the story branch. After every fix round, commit again. The review diff is
  `git diff <integration>...HEAD` plus any uncommitted paths. The rounds and retries counters are
  updated in the Execution block and committed before the dispatch they bound, so a builder that
  dies before committing still consumed its attempt.
- Parallel path: builders edit their worktrees and nothing is committed while a wave is running,
  because the Codex runner's git metadata fingerprint sees every ref in the repository and a
  commit on story A's branch fails story B's run. Once the wave has returned, the integration
  tail commits each story's build before its gates and proceeds as the sequential path does.
- `--no-ff` merges keep the round history. Squash is the user's choice and loses nothing the
  Execution block does not already hold.

## C. Hooks and runner

- `require-signoff.mjs` reads `docs/approval.json` and blocks implementation writes unless
  `status` is `approved`. When the marker is absent it falls back to the legacy
  `pm/pm-state.json` or `tmp/pm-state.json` `signed_off` field, so an un-migrated project keeps
  its gate. Fail-open otherwise.
- `pm-secrets-guard.mjs` guards `docs/` (the handoff, the plan, the wiki, the stories) and the
  legacy `pm/`.
- `actor-guard.mjs` is deleted, with its `hooks.json` entry and tests.
- `session-context.mjs` prints git-derived facts: approval status, the current branch and its
  story's Execution block, other claimed stories, worktrees, uncommitted path count, handoff
  freshness, the wiki line, and the resume pointer. Silent outside a managed project. A legacy
  `pm/` without a marker gets one line pointing at the migration.
- The Codex runner's build and fix modes require a tracked, regular `docs/approval.json` with
  `status: approved`. A project with legacy state and no marker is blocked with a message naming
  the migration. `docs/approval.json` and `docs/handoff/` join the protected paths.
- `hooks/lib.mjs` gains `readApproval(root)`, `parseExec(text)`, and `APPROVAL_REL`. The actor-id
  derivation is unchanged; it now names handoff files only.

## D. Migration (`migrations.md`, one section)

On any state read that finds `pm/pm-state.json` or `tmp/pm-state.json` and no
`docs/approval.json`, `/deliver:resume` migrates in one visible commit: write the marker from
`signed_off`, `approver`, and `approved_date`, with the current plan digest; write an Execution
block into every story an actor file or `assignments` names, from `resolved_builder`, `branch`,
the status, and the counters; read each old handoff once and fold anything still true into the
story's notes; remove `pm/`, the union-merge attribute, `.claude/rules/pm-state.md`, and the
plan's `Instruction rules` line. The log stays in git history. Pre-0.13 and pre-0.17 story
migrations are unchanged.

## E. Doctor (`state-health.md`)

Marker parses, tracked, status consistent with the plan's Sign-off line; `plan_digest` matches
`git hash-object docs/plan.md`, else DRIFT (plan changed since approval); every Execution block
parses and has an owner and an existing branch while unmerged; a story branch without an
Execution block and a claimed story without a branch; a quiet unmerged branch as a possibly stale
claim; worktrees with no story; handoff staleness; legacy `pm/` present; `tmp/` ignored; git
identity derivable.

`references/logging-and-state.md` becomes `references/state.md`. `resume-procedure.md`,
`state-health.md`, `migrations.md`, `implementation-loop.md`, `parallel-execution.md`,
`planning-and-signoff.md`, `discovery.md`, `specification.md`, `fix-loop.md`,

`approval.json.template` added; `story.md.template` gains the Execution section;
`HANDOFF.md.template` gains `BASE_COMMIT`; `plan.md.template` gains `Integration branch` and
drops `Instruction rules`; `pm-state.json.template`, `actor-state.json.template`,
`log.md.template`, `rules-pm-state.md.template`, `pm-AGENTS.md.template` are deleted.
`examples/todo-cli` carries `docs/approval.json`, Execution blocks, and `docs/handoff/`. README
and CHANGELOG describe the model; the version is 0.24.0.

## Acceptance criteria

- AC-1: no file under `plugins/deliver` names `pm-state.json`, `pm/log.md`, `pm/actors`, or
  `actor-guard` except the legacy fallback in `require-signoff.mjs`, the migration section, the
  session hook's legacy line, and the runner's migration message.
- AC-2: `require-signoff.mjs` blocks on `status != approved`, allows on `approved`, honours legacy
  `signed_off` when no marker exists, and fails open on a malformed marker.
- AC-3: the runner refuses a build without an approved marker and names the migration when only
  legacy state exists; `docs/approval.json` and `docs/handoff/` are protected paths.
- AC-4: the session hook prints approval, branch, story Execution state, claims, worktrees,
  uncommitted count, handoff freshness, and the wiki line, and is silent outside a managed project.
- AC-5: `examples/todo-cli` has no `pm/` and validates; `bash scripts/validate.sh` ends
  `validate.sh: OK`; the node tests are green; version and CHANGELOG at 0.24.0.
