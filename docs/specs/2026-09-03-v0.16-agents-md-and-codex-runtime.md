# v0.16 — AGENTS.md instructions layer and a cross-platform Codex runtime

Status: APPROVED by the user on 2026-09-03 (chat). Date: 2026-09-03. Supersedes the relevant sections of
`docs/specs/2026-09-03-v0.16-knowledge-restructure-proposal.md` (WS1, WS2, WS3). The wiki
(WS4) and SpecDD skeleton (WS5) are later releases and are out of scope here.

## Summary

Three changes ship together because they rewrite the same files (scaffold templates, every agent
prompt, the Codex commands, the runner, the hooks):

1. **AGENTS.md is the canonical project instructions file.** The PM scaffolds `AGENTS.md` and a
   one-line `CLAUDE.md` bridge whose first line is `@AGENTS.md`. Symlinks are not used.
2. **AGENTS.md carries facts only.** The template drops the restated workflow rules and file-by-
   file prose. Procedure lives in the skill, constraints in hooks, persona in agent bodies.
3. **One cross-platform Codex runtime.** A zero-dependency Node ESM runner replaces the bash
   runner, gains read-only modes, and every Codex invocation goes through a thin Sonnet wrapper
   agent. The PM never runs `codex` in the main session. The hooks move to Node in the same
   release so the plugin has no bash and no `jq` at runtime, on macOS, Linux, or Windows.

Decisions already taken by the user: import bridge (not symlink); minimal template; three thin
wrapper agents on one shared runner; Windows support without running bash.

## Goals

- A project scaffolded by the PM works unchanged under Claude Code, Codex CLI, Cursor, and
  Copilot, with one instructions file.
- Every subagent dispatch carries a small instructions file (target 30 to 40 lines, hard limit
  200 lines and 32 KiB, the Codex budget).
- Codex review, advice, research, build, and fix all run through the same runner with the same
  preflight, safety posture, exit codes, and result shape.
- The plugin's runtime scripts (runner and hooks) run on Windows natively via `node`.
- No behavioural regression for existing managed projects (see Migration).

## Non-goals

- Nested per-directory AGENTS.md files (SpecDD release).
- Path-scoped `.claude/rules/` shipped by default (optional, see B.3).
- Porting `scripts/validate.sh` or the CI harness off bash. Those are maintainer tools.
- Changing any model or effort regime. New agents follow the existing Sonnet wrapper rule.
- The plugin rename. If it happens it is a separate change layered on this one.

## A. Instructions layer

### A.1 Scaffold (references/planning-and-signoff.md section 3)

After sign-off the PM writes, in this order:

1. `AGENTS.md` from `templates/AGENTS.md.template`, if absent.
2. `CLAUDE.md` from `templates/CLAUDE.md.template`, if absent. Template content:

   ```
   @AGENTS.md
   <!-- Claude Code only. Everything shared with other agents belongs in AGENTS.md. -->
   ```

Existing files are never overwritten (current rule kept). Two new cases:

- `CLAUDE.md` exists, `AGENTS.md` absent: propose moving the content into a new `AGENTS.md` and
  replacing `CLAUDE.md` with the bridge. Show the diff and ask. On refusal, leave both alone and
  log that the project keeps a standalone `CLAUDE.md`.
- Both exist and `CLAUDE.md` is not a bridge: leave both, log a WARN, `/pm-skill:doctor` reports it.

### A.2 Readers

Every prompt that says "read CLAUDE.md" becomes "read `AGENTS.md`, and `CLAUDE.md` when it is
more than a pointer". Files: `agents/expert-builder.md`, `agents/test-engineer.md`,
`agents/debugger.md`, `agents/code-integrity-reviewer.md`, `agents/security-auditor.md`,
`agents/architecture-reviewer.md`, `agents/pm-verifier.md`, `agents/technical-writer.md`,
`commands/doctor.md`, `references/model-tiering.md` (override notes), and the Codex prompt
assembled by the runner (today `scripts/codex-builder-run.sh` line 267).

### A.3 Hooks

`require-signoff` adds `AGENTS.md` and `.claude/rules/*` to the pre-sign-off exemption list next
to `CLAUDE.md`. Test cases added for both.

### A.4 Doctor

New checks under a "Instructions" heading: `AGENTS.md` present; `CLAUDE.md` first line is
`@AGENTS.md` (or reports "standalone"); `AGENTS.md` line count under 200 and size under 32 KiB;
lines in `AGENTS.md` that duplicate skill hard rules (matched against a short phrase list) are
listed as trim candidates.

### A.5 This repo and the example

- Root `AGENTS.md` (validate command, layout, version-coherence and model-pinning gotchas, no
  bash at runtime rule) and a `CLAUDE.md` bridge.
- `examples/todo-cli/CLAUDE.md` becomes `AGENTS.md` plus bridge; its content is trimmed to the
  new template shape.

## B. Minimal AGENTS.md template

### B.1 `templates/AGENTS.md.template`

```markdown
# <Project>

<one or two lines: what this project is and why>

## Commands
- Test: `<cmd or N/A>`
- Lint: `<cmd or N/A>`
- Build: `<cmd or N/A>`
- Run: `<cmd or N/A>`

## Working here
- This project is delivered with the pm-skill plugin. Process rules live in that skill and are
  enforced by its hooks; do not restate them here.
- Delivery state lives in `pm/` and is git-tracked. Never edit another actor's
  `pm/actors/<id>.json`. `tmp/` is scratch and ignored.
- Never push to a remote without an explicit request.

## Layout
<three to eight lines: top-level directories and what lives where>

## Conventions
<only rules that differ from the language or framework default>

## Gotchas
<anything non-obvious a contributor must know>
```

Target 30 to 40 lines filled. The PM fills Layout from the codebase-analyst pack or the plan's
Architecture section and keeps it to directories, not files.

### B.2 Persona and procedure

New `references/instruction-layers.md` (about 40 lines) records the mapping so the PM never
copies procedure into `AGENTS.md` again:

| Layer | Holds | Where |
|---|---|---|
| Facts | commands, layout, non-default conventions, gotchas, safety norms | `AGENTS.md` |
| Procedure | phases, checklists, hand-off contracts | `SKILL.md` and `references/` |
| Constraints | sign-off, secrets, actor isolation, touches | hooks and the runner |
| Persona | role, tone, boundaries, stop conditions | each `agents/*.md` body; the runner prompt for Codex |

`SOUL.md` is named explicitly as not adopted: neither Claude Code nor Codex loads it, and the
agent bodies already carry the persona. A project author who keeps one may import it from the
bridge file; the PM does not create it.

### B.3 Optional path-scoped rules

At `standard` scale and above the PM may write `.claude/rules/pm-state.md` with
`paths: ["pm/**"]` containing the state discipline (claim, sync, never edit another actor). Codex
gets the same three lines in `pm/AGENTS.md`. Both come from templates. Off by default; the plan's
Delivery mode gains `Instruction rules: none | pm-state`. Default `none`.

## C. Cross-platform Codex runtime

### C.1 Runtime requirement

Node.js 20 or newer becomes a documented runtime requirement of the plugin. Rationale: it is
the only cross-platform scripting pattern the Claude Code hooks docs endorse, OpenAI's own
Claude Code plugin ships that way, and the npm route for both Claude Code and Codex already
assumes it. `jq` is no longer required. `/pm-skill:doctor` and the runner preflight report a
missing `node` with the install hint.

### C.2 Layout

```
plugins/pm-skill/scripts/codex/
  run.mjs            # CLI entry: --mode build|fix|review|advise|research
  lib/args.mjs       # argument parsing and validation
  lib/preflight.mjs  # codex on PATH, version, login status, exec --help capabilities
  lib/spawn.mjs      # cross-platform spawn, stdin prompt, timeout, process-tree kill
  lib/git.mjs        # toplevel, ls-files, hash-object, status, metadata fingerprint
  lib/snapshot.mjs   # before/after manifests and changed-path diff (build/fix only)
  lib/story.mjs      # pm-meta parsing and touches allowlist (build/fix only)
  lib/result.mjs     # runner JSON envelope and exit codes
plugins/pm-skill/scripts/tests/
  codex-run.test.mjs # node --test, stubbed codex, all modes, all exit codes
  hooks.test.mjs     # node --test, table-driven stdin fixtures (port of test-hooks.sh)
```

The bash runner, `scripts/test-codex-builder.sh`, and `scripts/test-hooks.sh` are deleted.
`scripts/smoke-codex-builder-live.sh` becomes `scripts/codex/smoke-live.mjs`, still opt-in via
`PM_CODEX_LIVE=1`.

### C.3 Runner CLI

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/codex/run.mjs" --mode <mode> [common] [mode options]

common:   [--model <id>] [--effort <level>] [--timeout-seconds <n>] [--preflight]
build:    --worktree <abs> --story <docs/stories/x.md>
fix:      --worktree <abs> --story <docs/stories/x.md> --evidence <tmp/codex-builder/x.md>
review:   --scope recent|worktree|codebase [--objective "<text>"] --out <dir>
advise:   --prompt-file <abs>
research: --prompt-file <abs> [--search auto|off]
```

Rules carried over from the bash runner: exit 64 usage, 65 rejected, 66 blocked, 69 unavailable,
70 failed, 74 safety violation, 124 timed out, 130 interrupted; model id regex; effort
allowlist; timeout 1 to 7200 seconds, default 600; `--preflight` never runs inference and emits
`quota_consumed:false`; no free-form CLI flags are accepted.

Defaults per mode: build and fix `gpt-5.6-sol` / `high`; review and research `gpt-5.6-terra` /
`high`; advise `gpt-5.6-sol` / `medium`. Identical to today's commands.

### C.4 Mode behaviour

- **build / fix**: exact port of the bash runner. Exact-root worktree check, fail-closed
  sign-off, tracked story, single `pm-meta` comment, touches allowlist, `--sandbox
  workspace-write`, fixed `-C`, host-temp exclusion, worktree-local runtime temp, reduced
  environment, disabled login shell, subagents, network, web search, MCP, and hooks, ignored user
  config and rules, `--output-schema`, before/after snapshots, git metadata fingerprint, safety
  violation on any out-of-scope change. Result envelope unchanged so `codex-builder`,
  `benchmark-builders`, and the scorer keep working.
- **review**: `codex exec review` with `--commit HEAD` (recent), `--uncommitted` (worktree), or
  `codex exec --sandbox read-only` with a whole-codebase prompt (codebase). With an objective the
  scope is expressed in the prompt, as today. The runner never passes `--sandbox`, `-C`, or
  `--color` to `exec review` (exit 2 otherwise). Output is written to a temp dir outside the repo,
  then moved into `--out`, which must be `untracked/` or `codex/` holding no tracked files; the
  runner appends the root-anchored `/<dir>/` rule to `.gitignore` when inside a git repo. The
  envelope returns `report_path`.
- **advise / research**: `codex exec --sandbox read-only --ephemeral --color never` with the
  prompt on stdin, `--ignore-user-config --strict-config`, `-o` to a scratch file outside the
  repo. `research` adds `--search` when `codex exec --help` lists it and `--search` is `auto`.
  `--skip-git-repo-check` is added when the cwd is not a git repo. The envelope returns
  `answer_path` and `stderr_path`.

### C.5 Windows behaviour

- Executable resolution: on `win32` resolve `codex` through `PATHEXT` (`codex.exe`, then
  `codex.cmd`). A `.cmd` shim is spawned through `cmd.exe /d /s /c` with argv built by the runner
  only from validated values; the prompt always arrives on stdin, never on the command line.
- Timeout kills the tree: `taskkill /T /F /PID` on win32, process-group signal on POSIX.
- Paths: `fs.realpathSync.native` for containment; git output normalised to forward slashes;
  worktree root compared case-insensitively on win32.
- Runtime temp: the runner sets `TMPDIR`, `TMP`, and `TEMP` to the worktree-local runtime dir.
- Sandbox: Codex's Windows sandbox is off by default, and with it off `codex exec` (approvals
  fixed to `never`) refuses every shell command that is not on Codex's known-safe list. Decision
  (user, 2026-09-03): do not enable the Windows sandbox. On win32, build and fix therefore pass
  `--sandbox danger-full-access` instead of `workspace-write`, and the network, temp-exclusion,
  and login-shell config keys that only exist inside the workspace-write sandbox are dropped on
  that platform. The envelope records `sandbox: "none (win32)"`. Everything the runner enforces
  itself still applies on Windows: sign-off fail-closed, tracked story, touches allowlist,
  before/after snapshots, git metadata fingerprint, out-of-scope change detected as a safety
  violation (exit 74, changes preserved for inspection), timeout, ignored user config and
  rules, subagents, web search, MCP, and hooks disabled through `-c`. The difference from POSIX
  is prevention versus detection: on Windows an out-of-scope write is caught after the run, not
  blocked during it. Review, advise, and research on win32 use `--sandbox read-only` as a
  policy shape only. **Verification item:** confirm on a Windows machine that
  `--sandbox danger-full-access` runs commands headlessly under `codex exec`.
- Bypass flags: the user has approved full access (`--yolo` /
  `--dangerously-bypass-approvals-and-sandbox`) for Codex. The runner expresses it as
  `--sandbox danger-full-access` on win32, which is the same thing under `codex exec` (approvals
  are already `never`). POSIX keeps `workspace-write` by default because it costs nothing. The
  "never pass bypass, full-auto, or yolo" sentences in agent and command prompts are replaced by
  "wrappers never pass sandbox or approval flags; the runner owns them per platform".
- Snapshots on win32 ignore the executable bit (git index mode for tracked files, `100644` for
  untracked).
- `.gitattributes` in the plugin pins `*.mjs text eol=lf`.

### C.6 Wrapper agents (all `model: sonnet`, `effort: medium`)

| Agent | Tools | Inputs | Runner mode | Returns |
|---|---|---|---|---|
| `codex-builder` (existing) | Bash | Story, Worktree, Mode, Evidence, overrides | build / fix | unchanged 20-line condensation |
| `codex-reviewer` (new) | Bash, Read | Scope, Objective, Out dir, overrides | review | 15-line digest: findings by severity, report path |
| `codex-advisor` (new) | Bash, Read | Brief (self-contained), overrides | advise | 20-line attributed answer, scratch path |
| `codex-researcher` (refactored) | Read, Grep, Glob, Bash, Write | Question, constraints, overrides | research | unchanged 15-line digest and `docs/research/*-codex.md` |

Each body follows the `codex-builder` shape: inputs, one runner call with every path quoted,
never other arguments, return contract, no retries on auth, safety, path, or unsupported-CLI
failures. `codex-researcher` loses its inline `codex exec` block and its scratch handling; it
still composes the brief and writes the attributed report.

### C.7 Commands become dispatchers

- `/pm-skill:codex-review`: parse arguments as today; run `--preflight --mode review` once;
  dispatch one `codex-reviewer` per objective in parallel with the Agent tool; write the index
  file when two or more reports exist; relay digests; log. The 30-second polling loop and the
  CLI recipes are removed.
- `/pm-skill:codex-help`: parse arguments; compose the brief; dispatch `codex-advisor`; relay
  the answer with the PM's own take; log. No `codex` call in the main session.
- `/pm-skill:benchmark-builders`: only the preflight command changes to the Node runner.
- `references/model-tiering.md` gains the rule: "The PM never runs `codex`. Every invocation
  goes through a Sonnet wrapper agent and the bundled runner." New agents join the pinned table.

## D. Hooks in Node

### D.1 hooks.json exec form

```json
{ "type": "command", "command": "node",
  "args": ["${CLAUDE_PLUGIN_ROOT}/hooks/require-signoff.mjs"] }
```

Same four hooks, same events and matchers: `session-context`, `require-signoff`,
`pm-secrets-guard`, `actor-guard`. Kill switch `PM_SKILL_NO_ENFORCE=1` unchanged. Fail-open
semantics unchanged: any uncertainty exits 0; a block exits 2 with the same stderr messages.
Each script resolves its own directory from `import.meta.url`, not from the env var, because
the placeholder's Windows form is inconsistent across Claude Code versions.

### D.2 lib.mjs

Ports `pm_root`, `pm_relpath` (realpath containment), `pm_secret_scan`, and `pm_actor_id`.
The actor id must stay byte-identical: the bash version hashes with POSIX `cksum` (CRC-32,
polynomial 0x04C11DB7, non-reflected, length appended). `lib.mjs` implements that CRC and the
test suite asserts fixed vectors captured from `cksum` on macOS and Linux, plus the salt string
`pm-skill` which does not change even if the plugin is renamed.

### D.3 Tests

`scripts/tests/hooks.test.mjs` ports every case in `scripts/test-hooks.sh` (stdin fixtures,
expected exit and stderr). `scripts/tests/codex-run.test.mjs` ports every case in
`scripts/test-codex-builder.sh` and adds review, advise, research, preflight-only, timeout, and
win32 argv-building cases. The stub `codex` is a Node script installed as `codex` on POSIX and
`codex.cmd` on Windows in a temp `PATH` entry.

## Migration for existing managed projects

- Nothing breaks on upgrade: hooks keep their semantics, `pm/` layout and actor ids are
  unchanged, `codex-builder` accepts the same dispatch, existing `CLAUDE.md` files are untouched.
- `/pm-skill:resume` prints a one-line suggestion when `AGENTS.md` is absent, pointing to the
  A.1 migration offer. `/pm-skill:doctor` reports the instructions layout.
- Projects that lack `node` see hook errors from Claude Code. README and doctor name the fix.

## Risks and open verification items

1. Windows runs without an OS sandbox (C.5): the runner detects out-of-scope writes after the
   run instead of preventing them. Accepted by the user. Headless behaviour of
   `--sandbox danger-full-access` under `codex exec` still needs one live check on a Windows
   machine with Codex installed; CI cannot cover it.
2. `${CLAUDE_PLUGIN_ROOT}` form on Windows. Mitigated by exec-form hooks and `import.meta.url`.
3. `cksum` port correctness. Mitigated by fixed test vectors captured before deleting `lib.sh`.
4. Node as a new hard runtime requirement. Accepted by design; surfaced by doctor and README.
5. Larger release than usual. If review capacity is short, D (hooks) can move to 0.16.1
   without changing A to C; the runner does not depend on the hooks port.
