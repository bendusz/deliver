# bstack 1.2.0: pressure scenarios, without and with each change

Date: 2026-11-13. Baseline: bstack 1.1.1 (`a1d3676`), extracted to a scratch directory. With: the
1.2.0 working tree, snapshotted before the runs.

## Method
Each run is one fresh subagent playing the PM. It reads `project-manager/SKILL.md` and whatever
references and templates the skill tells it to load for the moment described, and reads nothing
outside the plugin. It answers with DECISION, ACTIONS, MESSAGE and RULES. Every run uses
`claude-opus-5-5` except S8, which runs on `claude-fable-5-2` because the scenario puts the PM
there. The prompt is the same in both arms; only the plugin path changes. A run passes when its
reply meets the pass condition below. Every reply was read in full; none was scored by script.

Scenarios S2 and S4 passed at baseline and were run twice to confirm it. Following the rule that
a change whose scenario already passes is dropped, their new content came out (see Dropped). S2
and S4 ran once more in the with arm as regression checks.

The merge guard (S3) is also tested mechanically: `.github/scripts/test-scripts.sh` feeds the
hook real PreToolUse payloads against throwaway repositories (41 guard checks).

## Dropped, because the scenario passed without the change
- **Floor 2's new wording** ("split the rest into a new story", "never check the fix yourself")
  and the escalation bullet "never offer a merge with an open major". The 1.1.1 PM already
  escalated without merging, twice. Floor 2 keeps only the old hard rule's content.
- **The plan's `affected:` command** and gating on "the affected test projects". The 1.1.1 PM ran
  the full suite despite the `AGENTS.md` shortcut, twice. Gates stay the plan's full commands; a
  `## Waivers` row is the only way to narrow them. Floor 3 keeps "recorded with the sha", which
  the merge guard needs.
- **The pass-on-rerun classification prose** for the PM's own gate ("a defect unless a quiet,
  isolated rerun passes"). The 1.1.1 PM already treated it as a defect, and the prose would have
  loosened that. What stays is the reply's `reruns=` and error text, and the load rule.

## Dropped at the user's request
- **Tokens per child in the ledger.** T3 does not report token counts, and having the PM track
  them would take its attention off the work. The ledger keeps wall time and the model per role.

## Independent review of the scripts
Codex `gpt-6-astra` (high) reviewed the four new scripts before the commit. Every one of its
eleven findings reproduced, and each is fixed with a regression test in `test-scripts.sh`:
- The guard's command matching was a regex, which `command git merge`, a subshell, split quoting
  and a JSON-escaped `\/` all got past. It now decodes the JSON first and splits words as the
  shell quotes them. It checks every story operand, skips `-m` and `-F` values, and refuses an
  operand it cannot read.
- A record that named a ref instead of a sha passed, and so did a change made and then reverted
  after the gated sha. Records must now be full commit ids, and each later commit is checked, not
  only the end trees.
- `fixes-gate` was matched anywhere in `pm-meta`, and the Waivers lookup ran into the next
  section. Both are now bounded: `tags`, and the exact `## Waivers` section.
- `heavy.sh`'s `mkdir` locks could be reaped twice, or left behind by a holder that died before
  writing its pid. Locks are now pid symlinks made in one step, reaped under a mutex.
- `hygiene.sh` looped on a flag with no value, and `ledger.sh` accepted empty or table-breaking
  fields.

## Automated security review of the commit
Its three findings are fixed with tests. Switching branches and merging in one call
(`git switch main && git merge pm/…`) is refused, because the hook sees the branch from before the
call, wherever the HEAD-moving word appears, and a merge after a shell keyword (`then git merge`)
is parsed. A story name passed through `eval`, `xargs`, any shell's `-…c` flags, `git pull` or a
git alias is refused, whatever the cwd. Refusing every command that names a story was rejected:
it would block the PM's routine `git log` and `git diff` of story branches. When `heavy.sh` runs outside git, its lock directory is owner-only (mode 700) and
it opens lock files without truncating them. The guard catches mistakes, not an agent working to
get round it: a hard guarantee would need a git-level hook, which bstack dropped in 0.29.2.

## Board meeting, 2026-11-13
The board (sponsor `claude-opus-5-5`, engineering `gpt-6-astra`, customer `claude-fable-5-2`)
scored the branch 6/10 and made five recommendations. Each was handled like this:
1. **Merge guard.**
   - Without jq, python3 or node it refused every Bash call. It now exits on the raw input
     before decoding, so only a possible merge is refused for want of a reader.
   - The indirect-merge check refused commands outside bstack projects. It now applies only when
     the cwd, or a directory a `cd` or `-C` names, is a bstack project (or cannot be read).
   - `-C "$repo"` and `cd "$dir"` got past it. A story merge in a repository it cannot name is
     now refused.
   - Each fix has a test, and those tests fail against the previous guard.
2. **`docs/acceptance-differences.md` is a state file.** It is the fixed place for accepted
   differences, so recording one no longer voids the release candidate.
3. **The PR merge path** (`host.md`) now puts the same merge to the guard itself, instead of a
   hand-run end-tree diff.
4. **`/bstack:doctor` feeds the guard a payload it must refuse,** and reports `BROKEN` if it does
   not. The live smoke test of the installed hook is the user's.
5. **Rerunning the integration gate on resume: dropped.** The scenario passed without the change.
